# v2.0.0 namespace changes

919 of 1,710 real resource types (53.7%) move to a different package in
this release. Full list below: `wire_type  OLD service.local  ->  NEW
service.local`.

Root cause (UBI-98, `ubiquex`): the previous codegen derived a
resource's package purely by mechanically splitting its flat wire type
name on `_` and taking the second token as the service. That guess was
wrong in two distinct, real ways, both fixed by using CloudFormation's
own real namespace field directly instead:

- **AWS's historical EC2/VPC bare-name family.** `aws_instance`,
  `aws_vpc`, `aws_security_group`, and similar predate AWS's own
  `aws_<service>_*` naming convention and carry no service token at
  all. The old split put each one in its own tiny, wrong package
  (`instance/`, `vpc/`, `security/`). They now correctly land in `ec2/`.
- **Every multi-word real AWS service name.** `aws_api_gateway_deployment`
  split to service `api`, dropping `gateway` entirely. Real AWS service
  names are very often multiple words (API Gateway, Amazon MQ, Elastic
  Beanstalk, Kinesis Analytics, Media Convert, Route 53 Resolver,
  Service Discovery, Access Analyzer, and more) — every one of them was
  truncated to its first word only. They now correctly land in
  `apigateway/`, `amazonmq/`, `elasticbeanstalk/`, and so on.

This also resolves a real, live naming collision the old scheme could
not: `aws_vpc_endpoint` currently ships (in `1.0.0`) as
`AWS::OpenSearchServerless::VpcEndpoint`'s own content, not EC2's,
because the old bare-name matching had no way to know which real
service a Terraform-style name was "supposed" to mean. Real service
identity as the package key makes `ec2.VpcEndpoint` and
`opensearchserverless.VpcEndpoint` distinct by construction.
