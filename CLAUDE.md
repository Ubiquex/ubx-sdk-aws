# CLAUDE.md — ubx-sdk-aws

## What this is

Typed bindings for AWS (`[dynamic_providers.aws]` +
`[dynamic_provider_groups.aws_data_all]`, mixed CloudFormation/Smithy-sourced
via `ubx-provider-dynamic`), generated by `ubx sdk gen`
(`github.com/ubiquex/ubiquex`, the coordinating repo), for all three SDK
languages in one combined repo:

- `sdk/go/` — Go bindings, module `github.com/ubiquex/ubx-sdk-aws/sdk/go/v2`
  (a subdirectory Go module at major version 2, tagged `sdk/go/v2.Y.Z` — Go's
  own semantic import versioning requires the `/v2` path suffix once a module
  crosses v2)
- `sdk/typescript/` — TypeScript bindings, published to npm as `@ubx/sdk-aws`
  (npm, not JSR — the one language exception among these six repos)
- `sdk/python/` — Python bindings, published to PyPI as `ubx-sdk-aws`

`VERSION` at repo root records the real upstream spec this generation was
fetched from (sha256 + date + source URL — the CloudFormation registry zip)
— the provenance record for what's currently checked in, not a semantic
version.

## Publishing discipline

- Three independent registries, three independent version numbers per
  language — never assume they agree. Verify each directly before trusting
  parity: Go module proxy (`gh api repos/Ubiquex/ubx-sdk-aws/tags` — look for
  `sdk/go/v2.*`, the `/v2` path prefix matters), `npmjs.com/package/@ubx/sdk-aws`,
  `pypi.org/project/ubx-sdk-aws`. A commit to this repo's own `main` is NOT
  the same as "published" for any of the three (`ubiquex`'s own CLAUDE.md
  rule 8, UBI-131 — this repo's own first real publish once deleted a real
  committed file; verify a fix landed, don't assume).
- These bindings are generated, not hand-written — a real fix belongs in
  `ubiquex`'s own `sdk/codegen/` (or the upstream schema, if the bug is in
  what's being generated FROM, see `ubx-schema-aws`), then regenerated here,
  never hand-patched in the generated output directly.
